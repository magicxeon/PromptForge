# Dub & Sub Studio

## ส่งออกเสียงฉากเดิมพร้อมพากย์

ในหน้าส่งออก เลือก MP4 พร้อมเสียงพากย์ หรือ WAV เปิด “เก็บดนตรีและเสียงบรรยากาศเดิม” เพื่อผสมเสียงฉากกับเทคที่เลือก ระบบแยกเสียงบน GPU ตอนส่งออกครั้งแรกและใช้เสียงฉากเดิมอีกครั้งเมื่อเปลี่ยนเทค ปิดช่องนี้เพื่อส่งออกเฉพาะเสียงพากย์

เครื่องเซิร์ฟเวอร์ต้องใช้ Python ที่มี CUDA PyTorch, NumPy และ SoundFile ตั้ง `BANDIT_PYTHON` เพื่อระบุ interpreter ได้ ค่าเริ่มต้นบน Windows ใช้ venv-py313 ของ momelo-post-processing ตั้ง `BANDIT_RUNTIME_DIR` หากต้องการย้ายโมเดลจาก `server/data/bandit-v2` ภายในโฟลเดอร์นี้ให้วางไดเรกทอรี `src/bandit_infer` โดยใช้ชื่อ `bandit_infer` และไฟล์ `checkpoint-multi.ckpt` ตัวประมวลผลตรวจ SHA-256 ก่อนโหลด ติดตั้งจาก [แพ็กเกจรุ่นที่ทดสอบ](https://github.com/openmirlab/bandit-infer/tree/96ea0ec12aeb444f379c2f5145fb8ee58b58cf19) และ [น้ำหนัก BandIt v2 จากผู้พัฒนา](https://zenodo.org/records/12701995)

## ทดลองถอดและแปลทั้งฉากด้วย Gemini

1. เลือกวิดีโอหรืออัปโหลดจากเครื่อง ระบุภาษาเป้าหมาย ยุคสมัย และบริบทที่รู้จริง เช่น “ฉากเกิดในโรงเตี๊ยมสมัยจีนโบราณ หญิงเจ้าของร้านกำลังสนทนากับแขกหนุ่ม” ใช้กับ local admin ที่เปิดการสร้างจริงและตั้งค่า `GEMINI_API_KEY` บนเซิร์ฟเวอร์
2. สำหรับงานใหม่กด **สร้างและถอดด้วย Gemini** เพื่อเริ่มทันที สำหรับโปรเจกต์เดิมกด **ถอดใหม่ด้วย Gemini** ใกล้หัวข้อบทสนทนา ตรวจภาษาแล้วกด **ส่งเสียงให้ Gemini** ระบบส่งเสียงและบริบทไปยัง Google และคิดค่าบริการตามบัญชี API
3. อ่านซับจีนคู่กับไทยและเวลาเริ่ม–จบ กด **ใช้ซับชุดนี้** เพื่อแทนที่บทและการจับคู่เทคในไทม์ไลน์ หรือ **ยกเลิก** เพื่อเก็บชุดเดิม หากต้องการวัดความแม่น ให้ฟังต้นฉบับตรงชื่อสถานที่ คำเรียกตัวละคร และช่วงที่ดนตรีทับเสียง

รุ่นเริ่มต้นใช้ `gemini-3.5-flash-lite` รับคลิปยาวสูงสุด 5 นาทีต่อครั้ง ตั้งค่ารุ่นและขีดจำกัดใน [dub-scene-transcription.json](../../server/config/dub-scene-transcription.json) การเปิดผลเดิมของ revision และภาษาเดียวกันใช้ผลที่เซิร์ฟเวอร์เก็บไว้ [เอกสาร Gemini Audio](https://ai.google.dev/gemini-api/docs/audio)

## เปิดใช้งาน

ใช้ API ของ ModelPromptForge ที่พอร์ต 6500 และ frontend ใหม่ที่พอร์ต 6502 หลังอัปเดตโค้ดให้โหลด API และ Post-processing ใหม่เมื่อว่างจากงานเดิม ตัวเปิด frontend จะใช้ API ที่เปิดอยู่แล้ว รัน `npm.cmd run dev:web-next` แล้วเปิด `http://localhost:6502/dub-sub` หรือเลือก **Dub & Sub Studio** จากชื่อพื้นที่ทำงานข้างโลโก้ คู่มือ Voice และการตั้งค่าคีย์อยู่ใน [คู่มือ Seed Audio](009-seed-audio-manual.md)

1. ใน **โปรเจกต์** กด **สร้าง** แล้วอัปโหลดวิดีโอหรือเลือกผลงานที่มีอยู่ ระบุภาษาต้นฉบับหรือ Auto และเลือกภาษาเป้าหมายหนึ่งหรือสองภาษา ถ้าต้องการเริ่มด้วยเสียงต้นฉบับ ให้เลือกถอดเสียงตอนสร้าง
2. คลิกประโยคเพื่อไปยังเวลานั้น เปิดแทร็กภาษาที่ต้องการแสดงบนภาพ เลือก **แปลบทสนทนา** หรือแก้คำแปลรายประโยค นำเข้า SRT/VTT หรืออ่านซับฝังในวิดีโอแล้วตรวจข้อความก่อนแทนที่บท
3. ใน **รูปแบบซับ** เลือก Sans หรือ Serif สีขาวหรือเหลือง ขนาด และตำแหน่ง เปิด **ดูเฟรมจากตัวเรนเดอร์** ในหน้าส่งออกเพื่อตรวจการวางอักษรด้วยฟอนต์ชุดเดียวกับไฟล์จริง
4. ใส่ชื่อตัวละครแล้วเลือก **กำกับเสียงประโยคนี้** ปรับบทที่จะอ่าน เสียง อารมณ์ และจังหวะ ดูราคาและสร้างเทค ฟังพร้อมภาพ แล้วกด **ใช้เทคนี้** เพื่อวางบนไทม์ไลน์ กดเก็บเข้าคลังเมื่อต้องการใช้เสียงนั้นในงานอื่น
5. **ส่งออก** ใช้ SRT/VTT สำหรับซับภาษาเดียว WAV สำหรับเสียงพากย์ หรือ MP4 พร้อมเสียงและซับได้ถึงสองแทร็ก การแนบซับแยกคัดลอก video stream ต้นฉบับ ส่วนการฝังซับต้องเข้ารหัสภาพใหม่ ปุ่มดาวน์โหลดในโปรเจกต์อ้างถึง revision ที่ส่งออก

## ค่าและบริการที่เกี่ยวข้อง

**ลองจังหวะพากย์กับคลิปเดิม** เลือกประโยคที่มีการหยุดพูดกลางบรรทัดแล้วกด **ให้ Luna ย่อบทตามเวลา** หากตรวจพบเสียงพูด หน้าตรวจบทจะแสดงช่วงเวลาเทียบจากต้นประโยค หลังสร้างเทคให้ปิดแทร็กเสียงต้นฉบับเพื่อฟังกับภาพ เทคที่คลาดจังหวะจะระบุจุดให้ฟังทวนในแผงเสียงของช่วงบทนั้น เกณฑ์เริ่มต้น จบ และพักปรับได้ใน `timedDialogue.alignment` ของ [การตั้งค่าเสียงพากย์](../../server/config/dub-scene-transcription.json)

| ส่วน | ตำแหน่งและวิธีปรับ |
|---|---|
| หน้าจอ | `web-next/src/features/dub-sub/editor-config.json` กำหนดภาษา ขนาดหน้า ระยะ autosave ความยาว cue เริ่มต้น และรูปแบบส่งออก ข้อจำกัดที่ backend ตรวจยังมีผล |
| โปรเจกต์และสื่อ | `DUB_SUB_DATA_DIR` ใน `server/config/paths.js` ค่าเริ่มต้นเป็น `server/data/dub-sub/` แยก directory ต่อเจ้าของ ไฟล์ต้นฉบับและไฟล์ส่งออกอ่านผ่าน API ของโปรเจกต์ |
| เสียง | `server/config/voice-studio/{models,voices,policy}.v1.json` เป็นแหล่งข้อมูล catalog ของ API ใช้คีย์ของ Seed Audio ที่ server อ่านจาก `BYTEPLUS_SEED_SPEECH_API_KEY` |
| ฟอนต์ | `client/assets/dub-sub/fonts/` เก็บ Noto Sans/Serif สำหรับไทย จีนย่อ และจีนเต็มพร้อม OFL ติดตั้งซ้ำด้วย `node scripts/install-dub-sub-fonts.mjs` ตัวติดตั้งอ้างอิง Google Fonts revision เดียวกัน |
| ประมวลผล | FFmpeg/ffprobe อ่านวิดีโอ เตรียมคลื่นเสียง และส่งออก เมื่อตัวเปิด web-next เป็นผู้เริ่ม API จะเปิด Python worker บน loopback พอร์ตว่างและรอให้พร้อม หากใช้บริการที่เปิดแยก ให้ตั้ง `POST_PROCESSING_URL` และ `POST_PROCESSING_INTERNAL_TOKEN` ให้ตรงกับบริการนั้น |
| โมเดลภาษา | `post-processing-service/requirements-dub-language.txt` และ `post-processing-service/scripts/install_dub_language_models.py` ใช้กับ Python environment ของ Post-processing บน Windows ค่าเริ่มต้นสำหรับโมเดลแปลและ OCR คือ `D:\applications\momelo-post-processing\models\dub-sub` เปลี่ยนด้วย `DUB_LANGUAGE_MODELS` |
| การแปลและ OCR | Gemini รับบทต้นฉบับ ภาษาที่เลือก ยุคสมัยและเรื่องย่อเมื่อสั่งแปล แก้ภาษาปลายทางบน cue เดิม การอ่านซับฝังในภาพใช้ Tesseract และตั้ง CLI ผ่าน `TESSERACT_PATH` ได้ |

## ผลการตรวจและขอบเขต

- หน้า Editor ที่ 1366×768 เคยเริ่มพื้นที่คลื่นเสียงที่ y=764 หลังรวมแถบเครื่องมือและจัดความสูงตาม viewport เริ่มที่ y=599 และเห็นทั้งคลื่นเสียง ซับต้นฉบับ และซับไทย ความสูงเอกสารเท่ากับหน้าจอ ตรวจเพิ่มที่ 1440×900, 820×768 และ 390×844 ทดลองเล่นวิดีโอจริงข้ามประโยค เลื่อนไปประโยคท้าย และข้ามไปช่วงเงียบเพื่อยืนยันการติดตามแถวซ้าย

- ไทม์ไลน์ 40 นาที 3,000 ประโยคบน Chromium 151 (Windows, i7-12700H) แสดงคลิปใน DOM 4 ชิ้นตอนเห็นทั้งงานและ 52 ชิ้นตอนซูม หน่วยความจำ JavaScript ตอนเปิดประมาณ 30 MB และ p95 จาก click event ถึงการวาด selection 39 ms ตรวจการเลือกข้อความอังกฤษที่ 03:04 จากแทร็กอังกฤษขณะปิด Follow แถวบท ภาษาที่แก้ไข และ playhead ต้องเปลี่ยนตามกัน
- ทดสอบอัปโหลดที่ถูกปฏิเสธแล้วเลือกวิดีโอทดแทนในหน้าต่างเดิม บันทึกชื่อและภาษาลงโปรเจกต์เดียว ตรวจการเริ่มและหยุด worker บน Windows และตรวจ HTTP 200 จาก worker, API และ Projects ผ่านพอร์ต 6502
- ผู้ตรวจ UX ทดลองกลับจากคลังเสียงบนจอ 390 และ 1440 พิกเซล แผงกำกับเสียงกลับมาที่ประโยคเดิม ภาษาอังกฤษ และเวลา 2.525 วินาที พร้อมเสียงที่เลือกและโมเดลที่ใช้ได้ การเลือกเสียงอย่างเดียวส่งคำขอเขียนข้อมูล 0 ครั้ง
- ผู้ตรวจทดสอบออกจาก Editor ระหว่างรอคลื่นเสียงต้นฉบับและสลับผู้ใช้ระหว่างถอดรหัสเสียงเทค เบราว์เซอร์ยกเลิกคำขอ ปิด AudioContext และทิ้งผลที่กลับมาของผู้ใช้เดิม

- ทดสอบจากเบราว์เซอร์จริงโดยใช้โปรเจกต์แยก อัปโหลดคลิป เลือกสองภาษา เขียนบทไทย/จีน เปลี่ยนรูปแบบซับ บันทึก ส่งออกและอ่านเนื้อหา SRT เปิดใหม่ และคืนทรัพยากรวิดีโอหลังออกจากหน้า ตรวจขนาดหน้า 390, 820 และ 1440 พิกเซล
- ทดสอบการโหลด Editor ใหม่ขณะที่งานแปลยังดำเนินอยู่ ใช้งานเดิมจนผลปรากฏโดยส่งคำขอประมวลผลครั้งเดียว
- ทดสอบ FFmpeg กับคลิปสังเคราะห์สำหรับ waveform, การผสม WAV, แทร็กซับเดี่ยวและสองภาษา, MP4 ฝังซับ และเฟรม PNG จาก renderer เดียวกัน
- ทดสอบบริการแปลจีนเป็นไทย อ่านอักษรจีนจากภาพ และถอดเสียงคลิปภาษาอังกฤษด้วย Whisper tiny บน CUDA การใช้งานกับสำนวนละคร ชื่อเฉพาะ เสียงพูดซ้อน และคุณภาพพากย์จริงของผู้ให้บริการยังต้องฟังตรวจด้วยคลิปงาน
- ตรวจสิทธิ์ต่างเจ้าของ การเรียกซ้ำระหว่าง session การขัดแย้งของ revision การป้องกันลบเทคที่โปรเจกต์ใช้อยู่ และการปิดกั้นคำขอ local admin ที่ไม่มี CSRF หรือมาจาก origin อื่น ทดสอบสัญญา Seed Audio และ Credits ด้วย fixture การฟังผล BytePlus จริงและการเทียบยอด invoice ยังไม่ได้ทดสอบ
- การส่งออกแบบฝังซับสำหรับวิดีโอ HDR หรือ pixel format ที่ยังไม่ได้ตรวจจะแจ้งให้เลือกแนบซับแยก คุณภาพและการรักษาสีของวิดีโองานจริงต้องตรวจด้วยไฟล์ต้นฉบับของงาน
