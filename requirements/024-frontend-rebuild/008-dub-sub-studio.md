# Dub & Sub Studio — โปรเจกต์ซับและพากย์เสียง

เปิดใช้งานที่ `/dub-sub` บน frontend ใหม่แล้ว ผลตรวจด้วยคลิปทดสอบและรายการที่ต้องประเมินด้วยคลิปละครจริงอยู่ใน [คู่มือใช้งาน](011-dub-sub-operations.md) ดู [แบบหน้าจอและเกณฑ์ตรวจรับ](010-dub-sub-editor-design.md) และ [คู่มือ Seed Audio](009-seed-audio-manual.md)

## 1. ทางเข้าและขอบเขต

เมนูหลักแสดง Playground และ Dub & Sub Studio เรียงข้างโลโก้ เมื่อจอกว้างไม่เกิน 700px ให้รวมลิงก์ไว้ในเมนูแฮมเบอร์เกอร์ เน้นพื้นที่ทำงานปัจจุบันตาม URL รวมหน้าย่อยและการใช้ปุ่มย้อนกลับของเบราว์เซอร์ ผู้ใช้ปิดรายการด้วยการเลือกเมนู กด Escape หรือคลิกด้านนอกได้

ตัวสลับพื้นที่ทำงานบนหัวเว็บมี Playground และ Dub & Sub Studio เมื่อเข้า Studio ให้เปิด **โปรเจกต์** เมนูอีกตัวภายใน Studio คือ **Voice Studio** สำหรับสร้างเสียงตัวละคร เขียนบทเสียง และจัดการคลังเทคตาม [ข้อกำหนด Voice Studio เดิม](../023-voice-studio/000-master.md) เมื่อเปิดคลังจากประโยคในโปรเจกต์ ให้เลือกเสียงแล้วกลับมาที่ประโยคและเวลาเดิมได้

กรณีใช้งานหลัก: นำเข้าละครจีน → ถอดบทพร้อมเวลา → ตรวจคำแปลไทย → จับคู่ผู้พูดกับเสียงตัวละคร → ฟังเสียงพากย์พร้อมภาพ → ส่งออกซับ เสียง หรือวิดีโอ ผู้ทำซับอย่างเดียวส่งออกได้ตั้งแต่ตรวจคำแปลเสร็จ

## 2. Dashboard และ Create

**ข้อมูลภาษาและบริบทของโปรเจกต์** ตอนสร้างให้แสดงภาษาต้นฉบับและภาษาแปลสูงสุดสองภาษาก่อนส่วนเลือกไฟล์ ตามด้วยข้อมูลเสริมสองช่อง คือ “ยุคสมัยและแนวภาษา” และ “เรื่องย่อหรือบริบทของฉาก” ผู้ใช้พิมพ์ได้เองทั้งไทยและอังกฤษ เว้นว่างได้ และแก้ชื่อกับบริบทภายหลังผ่านหน้าต่าง “แก้ไขโปรเจกต์” ขนาดกลาง ข้อมูลอยู่ใน revision ของโปรเจกต์เดิม ตรวจโดยสร้าง เปิดใหม่ แก้ไข และล้างค่าได้โดย cue ไฟล์เสียงและคำแปลที่มีอยู่ยังครบ ขั้นนี้เก็บข้อมูลเตรียมไว้สำหรับการแปลด้วย Luna ในขั้นถัดไป

- มุมมองรายการและการ์ดใช้ชุดโปรเจกต์เดียวกัน เรียงตามเวลาที่แก้ล่าสุด แสดงภาพปก ชื่อ ระยะวิดีโอ ภาษาต้นทาง → ปลายทาง วันที่ สถานะ และการกระทำหลักตามภาพอ้างอิง แบ่งหน้าโดย cursor
- Create เปิดแบบฟอร์มสั้นสำหรับอัปโหลดหรือเลือกวิดีโอที่ผู้ใช้มีสิทธิ์ ตั้งชื่อ ตรวจตัวอย่างและระยะเวลา เลือกภาษาต้นทางหรือ Auto และภาษาปลายทาง จากนั้นเลือกเริ่มถอดเสียงหรือเปิดแก้ซับเอง
- แสดงสถานะจากงานจริง ได้แก่ นำเข้า ถอดเสียง แปล พร้อมแก้ไข กำลังส่งออก และส่งออกสำเร็จ เมื่อประมวลผลล้มเหลวระบุขั้นที่ล้มเหลวและลองใหม่เฉพาะขั้นได้ ปุ่ม Edit เปิดงานล่าสุด ปุ่ม Download แสดงเมื่อมีไฟล์ส่งออกสำเร็จ เมนูเพิ่มเติมรวมเปลี่ยนชื่อและเก็บเข้าคลัง
- Ready หมายถึงพร้อมแก้บท ส่วน Complete หมายถึงมีผลส่งออกของ revision ปัจจุบัน เมื่อแก้งานหลังส่งออกให้ระบุว่าไฟล์เดิมเป็นเวอร์ชันก่อนหน้า

## 3. Editor สำหรับกำกับบทกับภาพ

| พื้นที่ | พฤติกรรมที่ต้องได้ |
|---|---|
| หัวหน้า | กลับ Projects, เปลี่ยนชื่อ, Save พร้อมสถานะบันทึก, Export เมื่อออกจากหน้าขณะมีงานค้างให้เลือกบันทึกหรือกลับมาแก้ |
| บทด้านซ้าย | ค้นข้อความต้นฉบับหรือคำแปล แสดงเวลาเริ่ม–จบ ผู้พูด และสองภาษาคู่กัน เลือกแถวแล้ว seek วิดีโอและเลือกคลิปบน timeline แก้ข้อความ เพิ่ม แบ่ง รวม หรือลบช่วงพร้อม Undo/Redo |
| ภาพกลาง | เล่นวิดีโอตามสัดส่วน แสดงซับของแทร็กที่เปิด ณ เวลาเดียวกับเสียง Play/Pause, ก่อนหน้า/ถัดไปตามประโยค, timecode, volume และ fullscreen เลือกวนฟังประโยคเดียวเพื่อกำกับการอ่าน |
| Tracks ด้านขวา | จัดการ Captions, Transcription, Translation และเสียงพากย์ เพิ่ม caption หรือภาษาแปล เปิด/ซ่อนซับ ล็อกการแก้ไข เลือกแทร็กเสียงเพื่อ mute/solo หรือปรับระดับเสียง เลือกประโยคแล้วคงเครื่องมือที่กำลังใช้ เปิดรายละเอียดเสียงเมื่อผู้ใช้เลือก “กำกับเสียง” |
| Timeline ด้านล่าง | ไม้บรรทัดเวลา waveform ต้นฉบับ บล็อกซับแยกภาษา และคลิปเทคตามตัวละคร ใช้ playhead เดียวกับภาพและรายการบท ลากย้าย/ปรับขอบช่วง ซูมเวลา เลื่อนแนวนอน ดับเบิลคลิกช่องว่างเพื่อเพิ่มซับ มีช่องเวลาให้แก้ด้วยคีย์บอร์ด |

คลิกช่วงเวลาใด ให้เห็นแถวนั้น แทร็กนั้น และภาพในเวลาเดียวกัน เมื่อเล่นต่อ ให้เน้นประโยคที่กำลังพูดโดยรักษาตำแหน่งที่กำลังพิมพ์อยู่ จอเล็กให้คงภาพและ transport แล้วสลับแผง บท / Tracks / Timeline จอแท็บเล็ตพับแผงขวาได้ รองรับ UI ไทยและอังกฤษแยกจากภาษาของสื่อ คืน focus หลังปิดแผง และคง selection เมื่อบันทึก

## 4. ถอด แปล และพากย์ทับ

1. แยกเสียงจากสื่อที่นำเข้า เรียก ASR ผ่าน server ใช้ผลเวลาเป็นช่วงต้นฉบับ เก็บเวลาเป็นจำนวนเต็มมิลลิวินาที หากขาด timestamp ให้ระบุช่วงที่ต้องจัดเวลาเอง ผู้ใช้เพิ่มแถวเองได้ หากระบบให้ speaker labels ให้ผู้ใช้รวม/แยก/แก้ชื่อได้เสมอ
2. การแปลสร้างชั้นข้อความตามภาษา ผูกกับ cue ID เดิม ผู้ใช้แก้บทพากย์ให้อ่านธรรมชาติแยกจากคำซับได้ การถอดหรือแปลซ้ำต้องให้ตรวจการแทนที่ข้อความที่แก้มือ รองรับ retry รายช่วง
3. จับคู่ผู้พูดกับ character และเสียงจาก Voice Studio ครั้งเดียวต่อโปรเจกต์ เลือก override เฉพาะประโยคได้ แก้บท โทน และจังหวะตามความสามารถโมเดล กด “สร้างเทค” ผ่านขั้นตอน quote เดิม แล้วกด “ฟังเทค” เพื่อเล่นเทคที่มีพร้อมภาพ การฟังซ้ำใช้ไฟล์เดิม เทคทดลองเข้าสู่คลังเสียงเมื่อกด “เก็บเข้าคลัง”
4. เลือกใช้เทคแล้ววางคลิปอัตโนมัติที่เวลาเริ่มของ cue บนแทร็กตัวละคร วัดความยาวไฟล์จริง หากเสียงยาวเกินให้แสดงเวลาเกิน ฟังช่วงชน แก้คำ สร้างเทคใหม่ หรือขยับช่วงด้วยตนเอง เก็บเทคเดิมไว้จนกว่าจะเลือกแทน การเปลี่ยนเสียงของตัวละครระบุเทคที่ต้องทบทวน
5. ฟังเสียงต้นฉบับและพากย์พร้อมภาพ เลือกระดับเสียงต้นฉบับหรือปิดได้ สำหรับต้นฉบับที่ผสมบทพูดและเพลงในไฟล์เดียว การลดระดับมีผลกับทั้งไฟล์ แสดงแทร็กเพลงแยกเมื่อมีไฟล์แยกจริง
6. Export ให้เลือกภาษากับผลลัพธ์ ได้แก่ ซับ SRT/VTT, เสียงพากย์ผสม หรือวิดีโอพร้อมเสียงและตัวเลือกฝังซับ ตรวจ cue นอกความยาววิดีโอ แถวขาดเทค และเสียงซ้อนก่อนส่งออก ให้ผู้ใช้เห็นช่วงที่ได้รับผล สร้างไฟล์ตาม revision ที่เลือก ดาวน์โหลดซ้ำจาก Dashboard ได้

## 5. ข้อมูลและบริการ

โปรเจกต์เป็นเจ้าของ source media ID, revision, ภาษา, character mapping, tracks, cues และ export records แต่ละ cue มี stable ID, ช่วงเวลา, speaker, ต้นฉบับ, คำแปลแยกภาษา, บทพากย์ และ selected take ID เก็บเสียงผ่าน Voice Studio แล้วอ้าง ID ใน timeline แยกไฟล์สื่อจาก metadata ทุกการอ่าน/เขียนตรวจสิทธิ์เจ้าของที่ server ใช้ revision ตรวจการบันทึกทับจากหลายแท็บ งานระยะยาวต้องกลับมาอ่านสถานะหลัง reload และผูกคำขอซ้ำกับ operation เดิม

| งาน | เจ้าของและจุดเชื่อมต่อ |
|---|---|
| เสียง ตัวละคร และเทค | ใช้ `server/app/routes/voiceStudioRoutes.js` ผ่าน client API เดิม ได้แก่ catalog, characters, custom-voices, documents/rows, quotes, generations, selected-take, takes/save และ audio-library |
| ASR | มี internal `POST /v1/audio/transcribe` ใน `post-processing-service/api/routes.py` รองรับ language และ detectLanguage ขั้นเชื่อมต่อให้ตรวจผล timestamp/speaker ของ backend ที่ติดตั้งด้วย fixture ก่อนเปิดตัวเลือกใน UI |
| แปลและ export | ตรวจ service ของระบบสำหรับคู่ภาษา การสร้าง waveform, mix และ render ในขั้นทำ contract ก่อนเปิดใช้งาน แต่ละขั้นส่งสถานะ/ข้อผิดพลาดกลับระดับโปรเจกต์ แยกงานถอดต้นฉบับจากซับที่ผู้ให้บริการสร้างให้เสียงพากย์ |
| Seed Audio | เพิ่ม adapter หลัง Voice Studio generation ตามคู่มือ ผูก model/availability/credentials/ราคา ผ่าน server เช่นเดียวกับโมเดลเดิม ทุกการสร้างเสียงใช้ quote และ operation lifecycle เดิม |

## 6. JSON configuration สำหรับ frontend

ค่าหน้าจออยู่ใน [editor-config.json](../../web-next/src/features/dub-sub/editor-config.json) และตรวจ schema ที่ feature boundary ภาษา ขนาดหน้า จำนวนแถวบทบนจอ เวลา autosave ระยะ cue เริ่มต้น ระดับซูม และรูปแบบส่งออกปรับได้ที่นี่ ตัวอย่างค่าเริ่มต้นคือรายการ 20 โปรเจกต์ต่อหน้าและบันทึกหลังหยุดแก้ 1,400 มิลลิวินาที เมนู Studio ใช้ routes ของ FE24 ฟอนต์ใช้ไฟล์ OFL ชุดเดียวกับ renderer

API configuration ยึด [กระบวนการเดิม](../023-voice-studio/003-model-configuration.md) ผ่าน server catalog ที่ตรวจ schema และสิทธิ์ก่อนส่งให้ browser รายการโมเดล ภาษา ความสามารถ เพดานราคา และ availability มาจาก API ตัวเลือกที่แสดงเป็นผลร่วมของ UI config และความสามารถจริงของ API ค่าเฉพาะโปรเจกต์และเนื้อหางานบันทึกกับโปรเจกต์ Secret เก็บฝั่ง server

## 7. ลำดับส่งมอบและเกณฑ์ตรวจ

| งาน | ตรวจจบเมื่อ |
|---|---|
| 1. โครงหน้าและ config | สลับ Playground/Studio ได้ เปิด Voice Studio จาก Studio ได้ เปลี่ยน page size ใน JSON แล้วรายการโหลดตามค่า |
| 2. Project และ Editor | สร้างจากวิดีโอแนวตั้ง เปิดต่อหลัง reload และเลือก cue แล้ววิดีโอ/แทร็กตามกันทั้ง desktop, tablet, mobile |
| 3. ถอดและแปล | ทดสอบคลิปจีนพร้อมคำแปลไทย แก้หนึ่งประโยคแล้วภาษาอื่นและเวลาต้นฉบับอยู่ครบ กู้คืนงานล้มเหลวได้ |
| 4. Voice และ Seed Audio | ทดสอบโมเดลเดิมและ adapter ใหม่ด้วย fixture สองตัวละคร เลือกเทค วางเสียงถูกช่วง ตรวจ overrun, duplicate submit และ timeout ระหว่างรับผล |
| 5. บันทึกและส่งออก | เปิดงานอีกครั้งแล้วได้เทคและเวลาที่เลือก SRT/VTT ตรงกับ timeline ไฟล์เสียงและวิดีโอเล่นได้ ดาวน์โหลดเฉพาะไฟล์สำเร็จตามสิทธิ์เจ้าของ |

## 8. รายละเอียดหน้าจอและแนวทางประมวลผล

- Create รับทั้ง upload จากเครื่องและเลือกสื่อเดิม แสดง progress และตรวจไฟล์ด้วย ffprobe เก็บต้นฉบับไว้สำหรับ export เลือกภาษาต้นทางหรือ Auto แยกจากภาษาเป้าหมาย ข้อเสนอสำหรับรุ่นแรกคือสูงสุด 2 ภาษาเป้าหมายต่อโปรเจกต์ ตัวอย่างต้นทางจีนและเป้าหมายไทย/อังกฤษ ค่าเพดานแสดงผ่าน configuration และตรวจซ้ำที่ server
- Editor ใช้ React/TypeScript ใน web-next, HTML video เป็นนาฬิกากลาง, Canvas วาด waveform จาก peaks ที่ worker เตรียม, Web Audio เล่นและปรับ gain ของเทคตาม playhead เดียวกัน การ seek/pause/เปลี่ยนประโยคต้องจัดเสียงให้ตรงใหม่ แยกตำแหน่งซับในภาพ (พิกัดสัดส่วนของพื้นที่วิดีโอจริง) จากเวลา cue และ offset ของคลิป WAV
- แผง Tracks ให้เปิด inspector ของภาษาที่เลือก ใช้ 2 preset ฟอนต์ คือ Sans (Noto Sans Thai + Noto Sans CJK SC) และ Serif (Noto Serif Thai + Noto Serif CJK SC) เลือก glyph ตามภาษาและ variant ที่รองรับ ใช้ไฟล์ฟอนต์เวอร์ชันเดียวกันทั้ง preview และ render ตัวเลือกสีขาวหรือเหลืองพร้อมเงาดำ ปรับขนาด ตำแหน่ง จำนวนอักขระต่อบรรทัด เปิด/ซ่อน และ reset ต่อแทร็ก รองรับเปลี่ยนอักษรจีนย่อ/เต็มโดยคงเวลา, re-transcribe, OCR ซับฝัง และ import SRT/VTT ผู้ใช้ตรวจข้อความก่อนแทนบทที่แก้มือ
- เพิ่ม inspector กำกับพากย์ของประโยค แสดงตัวละคร/เสียงหลัก ภาษาพูด บทที่จะอ่าน อารมณ์ ความเข้ม จังหวะและคำกำกับอิสระ พร้อมเวลาเป้าหมายและความยาวเทคจริง ใช้ค่าเสียงประจำตัวละครและ override ราย cue ฝั่ง server แปลงเสียงที่เข้ากันได้เป็น speaker/reference และแปลงคำกำกับเป็น text_prompt ตาม adapter เก็บ snapshot กับเทคเพื่อเทียบเวอร์ชัน ให้แก้เทคเฉพาะประโยคก่อนเลือกวางบน track
- JSON ฝั่ง frontend เก็บ preset IDs, สี เงา ขนาดตั้งต้น safe margins, UI limits และปุ่มลัด ส่วน capability จริงมาจาก API catalog ตามข้อ 6 แยก secret และ provider config ไว้หลังบ้าน
- Backend ใช้ Node/Express ประสาน project/job/Voice Studio และ FastAPI post-processing ทำ ASR, peaks, mix และ export ให้ตรวจคุณภาพ Whisper แบบ multilingual กับภาษาไทย/จีนก่อนเลือกขนาดโมเดล OCR และ translation เป็น adapter ที่ต้องตรวจผลด้วยคลิปจริงก่อนเปิดใช้
- Export เลือกเก็บ video stream เดิมแล้ว mux เสียง/ซับแยกเมื่อ container รองรับ หรือเลือกฝังซับด้วย ASS/libass ผ่าน FFmpeg ที่ความละเอียดต้นฉบับ โหมดฝังซับต้อง encode ภาพใหม่ ใช้ preset คุณภาพสูงตาม codec ต้นทาง ตรวจ rotation, display aspect, frame timestamps, color metadata และ HDR compatibility ใช้เส้นทาง preview ขั้นสุดท้ายที่เรนเดอร์เฟรมตัวอย่างด้วยฟอนต์และ renderer เดียวกับ export
- เกณฑ์รับงานเพิ่ม: ทดสอบ upload และเลือกสองภาษา, สองตัวละครใช้อารมณ์ต่างกัน, font ภาษาไทยมีสระบน/ล่างและจีนไม่มีตัวสี่เหลี่ยม, ซับสองภาษาไม่ทับกัน, เทียบ preview กับ export ของคลิปแนวตั้งและแนวนอนที่ timecode เดียวกัน ตรวจภาพและเสียงท้ายคลิปว่ายังตรงกัน ดูผลทดสอบที่ทำแล้วและขอบเขตที่ต้องตรวจด้วยคลิปงานจริงใน [คู่มือใช้งาน](011-dub-sub-operations.md)
