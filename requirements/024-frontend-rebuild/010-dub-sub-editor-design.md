# Dub & Sub Studio — แบบหน้าจอและส่วนประกอบของ Editor

ข้อกำหนดประกอบ [workflow และสัญญาข้อมูล](008-dub-sub-studio.md) สำหรับ frontend ใหม่ใต้ workspace switcher หนึ่งโปรเจกต์มีเวลาอ้างอิงเดียวตั้งแต่ตรวจบทถึงส่งออก เอกสารนี้รวมผลรีวิวของ UX/UI Agent จากภาพ Projects, Editor, แผงฟอนต์ และภาพขณะตรวจคำแปล สถานะเป็นแบบสำหรับลงมือพัฒนา

## 1. หน้าจอที่ผู้ใช้เดินผ่าน

| หน้าหรือจังหวะ | สิ่งที่เห็นและคำสั่งหลัก | เมื่อทำงานต่อหรือย้อนกลับ |
|---|---|---|
| Projects | ปุ่มสร้างมุมขวาบน สลับรายการ/การ์ด แถวแสดงปก ชื่อ ความยาว คู่ภาษา สถานะ และเปิดแก้ไข ให้ Download กับ revision ที่มีไฟล์พร้อม | กลับมาแล้วอยู่หน้าและตำแหน่งเดิม งานที่กำลังทำแสดงขั้นจริง กดดูเหตุที่ล้มเหลวและเริ่มใหม่เฉพาะขั้นได้ |
| Create | เลือกไฟล์จากเครื่องหรือสื่อเดิม ดูปก/ระยะเวลา ตั้งชื่อ เลือกต้นทางหรือ Auto และเป้าหมายสูงสุดสองภาษา แสดงชื่อและขนาดไฟล์ขณะอัปโหลด | ยกเลิก/ลองใหม่ได้โดยเก็บชื่อกับภาษาที่เลือก เมื่อสื่อนำเข้าสำเร็จเริ่มถอดเสียง หรือนำเข้า SRT/VTT หรือเริ่มบทว่าง |
| ตรวจบทและคำแปล | ซ้ายแสดงต้นฉบับและภาษาเป้าหมายที่กำลังแก้พร้อมเวลา กลางเป็นวิดีโอ ใต้ภาพเป็น transport และ timeline เมื่อมีสองภาษาเป้าหมายให้สลับด้วยตัวเลือกที่หัวบท | คลิกประโยคแล้ว seek และเลือกคลิปเดียวกัน เปลี่ยนภาษาคง cue และเวลาไว้ เมื่อแปลภาษาที่สองล้มเหลว ให้ตรวจภาษาแรกต่อได้ |
| ปรับซับ | ลากข้อความบนภาพขึ้นลงได้ทันที หรือโฟกัสข้อความแล้วใช้ลูกศรขึ้นลง แผงรูปแบบซับใช้เลือกฟอนต์ Sans/Serif สีขาวหรือเหลือง ขนาดและการตัดบรรทัด | คงพิกัดแนวนอนของแต่ละแทร็ก เก็บความสูงเทียบกับพื้นที่วิดีโอจริงเมื่อปล่อยลาก Undo ย้อนการลากได้ในครั้งเดียว |
| กำกับพากย์ | เลือก cue แล้วกด “กำกับเสียง” แผงขวาแสดงตัวละคร เสียง/โมเดล บทพูด อารมณ์ ความเข้ม จังหวะ ช่วงเวลา และรายการเทค เลือกเสียงพากย์ในแผงเดียวกัน | กลับมาที่ cue ภาษาและ timecode เดิม ใช้เสียงหลักหรือ override เฉพาะประโยค เมื่อใช้เทค วาง WAV บนแทร็กตัวละคร มี waveform จริง ป้ายเวลาเกินและปุ่มวนฟังจุดชน |
| Export | เลือกผลลัพธ์ ภาษา แทร็กเสียงและรูปแบบซับใน dialog เดียว สรุปชื่อไฟล์ revision และช่วงที่ต้องตรวจ กดปัญหาเพื่อกลับไป cue นั้นได้ | ซับอย่างเดียวข้ามงานเสียงได้ งาน export อ่าน snapshot ณ เวลาสั่ง ผู้ใช้เปิดดูสถานะและดาวน์โหลดจาก Projects ได้หลัง reload |

## 2. การจัดพื้นที่ตามภาพอ้างอิง

- **Desktop** หัวจอคงชื่อโปรเจกต์ สถานะบันทึก และ Export พื้นที่ทำงานสามส่วนคือบท วิดีโอ และ Tracks; ใน Tracks แสดงเครื่องมือเฉพาะงานที่เลือก เครื่องมือกำกับเสียงและฟอนต์ใช้พื้นที่แผงเดียวกัน ใต้ภาพรวมปุ่มเล่น เวลา วนฟัง และ volume ไว้จุดเดียว ใต้ transport เป็นไม้บรรทัด คลื่นต้นฉบับ บล็อกซับ และคลิปพากย์ แถบปรับขนาดให้พื้นที่ที่เหลือแก่ภาพ
- **Tablet ประมาณ 820px** คงบทกับภาพคู่กันเมื่อพื้นที่พอ เปิด inspector ตามคำสั่งและพับคืนได้ **มือถือประมาณ 390px** คงภาพและ transport ไว้ด้านบน เลือกบทหรือ timeline ด้านล่าง เปิด inspector เป็นแผงจากขอบจอแล้วกลับมาดูภาพที่เวลาเดิม ให้เลื่อนแนวนอนเฉพาะ timeline
- ใช้พื้นกลางเรียบ สีเน้นสำหรับคำสั่งหลัก จุดเล่น และแถวที่เลือก มีชื่อ/สัญลักษณ์ประกอบสถานะเพื่อให้แยกได้แม้ไม่เห็นสี จัดคำสั่งรองใต้เมนูของแทร็ก ให้พื้นที่คลิกบนจอสัมผัสใช้งานได้แม้เส้นขอบคลิปบาง
- ระหว่างเล่นให้แยก **ประโยคที่ได้ยิน** กับ **ประโยคที่กำลังแก้** ใช้ปุ่ม “ตามตำแหน่งเล่น” เพื่อกลับมาไล่ตามบท ระหว่างพิมพ์ ให้รักษา caret, selection และการประกอบตัวอักษร IME เมื่อ autosave, scroll หรือเปลี่ยน cue ที่กำลังเล่น Space และลูกศรทำงานในช่องพิมพ์ตามปกติ
- แยกการเลือกภาษาเพื่อแก้ การเปิดแทร็กบนพรีวิว และการรวมใน export ในตัวอย่างผู้ใช้เห็นจีนและไทยในรายการบท เปิดเฉพาะไทยบนภาพ และเลือกส่งออกทั้งสองภาษาได้ ให้ลากเวลาโดยมีตัวเลขเริ่ม/จบเป็นทางเลือก ใช้คีย์บอร์ดเลือก cue ปรับขอบเวลา ปรับตำแหน่งซับ แล้วคืน focus สู่คำสั่งเดิมเมื่อปิดแผง
- เมื่อใช้ OCR กับข้อความฝังในภาพวิดีโอ ให้พรีวิวข้อความที่อ่านได้ก่อนรวมเข้าแทร็ก ปุ่มซ่อนซับมีผลกับ overlay ของโปรเจกต์ สี ฟอนต์ และตำแหน่งสำหรับสองภาษาปรับแยกและเลี่ยงการซ้อนกัน ตรวจสระ/วรรณยุกต์ไทยและอักษรจีนย่อ/เต็มกับไฟล์ฟอนต์ที่เลือกจริง
- Voice Inspector แยก “สร้างเทค” “ฟังเทค” “ใช้เทคนี้” และ “เก็บเข้าคลัง” แสดง estimated usage ผ่านนโยบายเดิมก่อนสร้าง และแสดงเทคที่ใช้อยู่บน timeline หลังเลือกใช้ สำหรับ Seed Audio แยกบทพูดจากคำกำกับ ส่ง voice reference ที่รองรับกับคำบรรยายการแสดงผ่าน adapter ผู้ใช้ฟังซ้ำได้ทันทีจากไฟล์ที่ได้มา [คู่มือ Seed Audio](009-seed-audio-manual.md)

## 3. Component ที่ค้นจากเอกสารต้นทาง และข้อเลือกสำหรับรุ่นแรก

ชุดที่มีใน web-next แล้วคือ React/TypeScript, React Router, TanStack Query, Radix Dialog, Lucide, i18next และ Zod ส่วนแพ็กเกจที่เสนอเพิ่มด้านล่างต้องทดลองกับสื่อและเบราว์เซอร์ของระบบก่อนล็อกเวอร์ชัน ข้อสรุปเรื่องความเร็วเป็นเป้าตรวจรับ ไม่ใช่ผล benchmark

| ส่วน | ตัวเลือกและวิธีใช้ในโปรเจกต์ |
|---|---|
| Dashboard, Create, Inspector | ใช้ตาราง/การ์ด CSS, file input และ Radix Dialog เดิมสำหรับ Create/Export ใช้ labels และ focus return เดิม ฟอร์มเลือกเสียงเรียก Voice Studio catalog และ API ของตัวละคร/เทคตาม [Voice Studio](../023-voice-studio/000-master.md) สำหรับแถบซูมหรือ gain เริ่มด้วย native range; Radix Slider เป็นทางเลือกเมื่อจำเป็นต้องคุม thumb หลายตัวผ่าน touch และ keyboard [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) · [Slider](https://www.radix-ui.com/primitives/docs/components/slider) |
| ขนาดแผง | เสนอ react-resizable-panels บน desktop ใช้กลุ่มแนวนอนสำหรับบท/ภาพ/Tracks กับ separator ที่ใช้คีย์บอร์ดได้ และกลุ่มแนวตั้งสำหรับ timeline มือถือใช้ layout สลับแผงตามข้อ 2 ค่าตั้งต้น/ต่ำสุดอยู่ใน UI JSON [react-resizable-panels](https://github.com/bvaughn/react-resizable-panels) |
| รายการบทสองภาษา | เสนอ TanStack Virtual เมื่อ cue มีจำนวนมาก ใช้ stable cue ID, วัดความสูงจริงตามการตัดบรรทัดและภาษา เก็บข้อความที่กำลังแก้ใน draft และเก็บแถวที่มี focus ไว้ระหว่าง composition การค้นหาต้องครอบคลุมบททั้งหมดแม้แถวยังไม่ปรากฏ [TanStack Virtual](https://tanstack.com/virtual/latest/docs/introduction) |
| วิดีโอและ playhead | ใช้ HTML video กับวิธีส่ง private media ของระบบเดิม แยกส่วนที่นำกลับมาใช้ได้จาก VideoViewer ซึ่งรับ VideoTask ส่วน editor รับ project media ใช้ mediaTime จาก requestVideoFrameCallback เพื่ออัปเดต playhead และซับ เมื่อไม่มี API นี้อ่าน currentTime จาก media element ระหว่างเล่น เมื่อ seek/pause ให้จัดเสียงที่กำลังเล่นตามเวลาใหม่ [Video frame callbacks](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback) |
| Waveform และ timeline | เลือก **Peaks.js** เป็นตัวทดลองหลักสำหรับคลื่นต้นฉบับ เพราะอ่าน peaks ที่สร้างไว้ฝั่ง server และผูกกับ media element ได้ ใช้ DOM สำหรับ cue/แทร็กตัวละครที่อยู่ในช่วงเวลาที่มองเห็น ทุก lane ใช้ time-to-pixel, scroll origin, zoom และ playhead ชุดเดียวกัน เก็บ start/end เป็น ms ตอนปล่อยลาก และใช้ Web Audio สำหรับ gain/mix ของเทค ทางเลือกคือ **wavesurfer.js** กับ pre-decoded peaks และ duration หากการผูก viewport ของ Peaks.js กับ timeline ไม่ผ่านการทดลอง ใช้ renderer เพียงตัวเดียว และโหลดเฉพาะเมื่อเข้า Editor [Peaks.js](https://github.com/bbc/peaks.js) · [wavesurfer.js](https://wavesurfer.xyz/docs/) |
| Subtitle preview และ export | เริ่มด้วย overlay ที่แก้ได้บน video เพื่อวางตำแหน่งและเลือกฟอนต์ พร้อมปุ่มดูเฟรมจาก FFmpeg/libass ที่ใช้ส่งออกจริง ถ้าพรีวิวแบบเล่นต่อเนื่องต่างจากเฟรมจริงเกินเกณฑ์ ให้ทดลอง **JASSUB** ซึ่งรองรับ ASS และการระบุไฟล์ฟอนต์ผ่าน worker/WASM ใช้ font assets ชุดเดียวกับ server พร้อมตรวจการโหลด worker บน frontend ใหม่ ก่อนยอมรับต้นทุนดาวน์โหลด สำหรับไฟล์ส่งออกเก็บ stream เดิมเมื่อ mux ได้ และ encode คุณภาพสูงจากต้นฉบับเมื่อฝังซับ [JASSUB](https://github.com/ThaUnknown/jassub) · [FFmpeg subtitles filter](https://ffmpeg.org/ffmpeg-filters.html#subtitles-1) |
| Upload | เริ่มด้วย file picker และ upload ของระบบที่แสดง progress จริง หากต้อง resume หลังการเชื่อมต่อขาด ให้ประเมิน Uppy Tus ต่อเมื่อ backend มี tus endpoint ที่รักษาสิทธิ์เจ้าของและ offset ได้ การเพิ่ม component ฝั่ง browser อย่างเดียวไม่ทำให้ upload resume ได้ [Uppy Tus](https://uppy.io/docs/tus/) |

## 4. ขอบเขต state และ configuration

Dub & Sub เป็นเจ้าของ cue, tracks, time mapping, edit history, selection และ revision ของโปรเจกต์ React Query ใช้กับ server state และ status งาน ส่วน playhead และ drag preview อยู่ใน editor ระหว่าง drag และ playback ให้ update เฉพาะพื้นที่ที่เปลี่ยน ส่งหนึ่ง edit เมื่อจบ gesture และรวมเป็นหนึ่ง Undo เมื่อเปลี่ยนโปรเจกต์หรือ actor ให้หยุด playback, ยกเลิกคำขอ และคืนทรัพยากร worker/audio/peaks

เพิ่มคีย์ใน UI JSON ของข้อ 008 สำหรับ panel defaults/minima, breakpoints, timeline steps/snap, cue overscan, autosave, font presets, subtitle colors/shadow, safe-area และรายการ shortcut มี schema version และ fallback ที่ทดสอบได้ ผู้ใช้เปลี่ยนค่าเฉพาะโปรเจกต์ให้บันทึกลง revision ของโปรเจกต์ ความเข้ากันได้ของเสียง โมเดล ภาษา ค่าใช้จ่าย และขีดจำกัดจริงให้ server catalog/quote เดิมเป็นผู้ตัดสิน

## 5. ลำดับทดสอบก่อนเลือกแพ็กเกจและเกณฑ์รับงาน

1. สร้าง fixture แนวตั้งและแนวนอน มีภาพ/เสียงอ้างอิงจุดเริ่ม กลาง ท้าย ประโยคไทยที่มีวรรณยุกต์ จีนย่อ/เต็ม สองตัวละครพูดซ้อน และสองภาษาเป้าหมาย ตรวจการเล่น pause, seek, loop, zoom และ drag ให้ตำแหน่งวิดีโอ cue คลื่นเสียง และเทคสัมพันธ์กับ timestamp เดียวกัน เทียบ export กับเฟรมจริง ณ timecode เดียวกัน ต้องคงการขึ้นบรรทัด ตำแหน่ง สี เงา และ glyph ครบ
2. ทดลอง Peaks.js กับวิดีโอ 40 นาทีและบทอย่างน้อย 1,000 cue โหลด waveform จาก peaks ที่เตรียมไว้ก่อน วัดเวลาเปิด Editor, จำนวนแถว DOM, memory และการตอบสนองระหว่างลาก/พิมพ์ บันทึกรุ่น browser, เครื่องและ fixture ด้วย เป้าหมายเสนอสำหรับ desktop คือ p95 เลือกแถวถึงแสดง selection ภายใน 100 ms หลังข้อมูลพร้อม แถว DOM เพิ่มตาม viewport + overscan/แถวที่แก้อยู่ ตรวจ timeline RAM หลังเปิดปิดโปรเจกต์ซ้ำ และยืนยันว่าเปิด Projects แล้วไม่ดาวน์โหลด waveform/WASM ของ Editor
3. ทดสอบที่ 390/820/1440px ใน UI ไทยและอังกฤษ รวม keyboard-only และ touch กรณีเลือกแถวระหว่างเล่น พิมพ์ด้วย IME ขณะ autosave ปรับฟอนต์ เลือกเสียงใน Editor ลากคลิป และโหลด revision ใหม่ ต้องคง draft/โฟกัสตาม workflow ระบุ timecode และ cue ID หาก sync ผิด
4. ทดสอบ upload ถูกยกเลิก, ASR ไม่มี timestamp, แปลสำเร็จเพียงภาษาเดียว, font โหลดล้มเหลว, สร้างเทค timeout, เทคยาวเกิน และ export ล้มเหลว ผู้ใช้เห็นขั้น/ช่วงที่ต้องแก้และกลับทำต่อได้ ฟังเทคเดิมและเปิดผลสำเร็จก่อนหน้าได้ เก็บสถานะงานแยกต่อภาษาและเทค เมื่อ autosave ชน revision ให้เก็บ draft และเสนอเทียบ/โหลด revision ก่อนทับงาน
