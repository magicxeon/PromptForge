# เสียงพากย์ตัวละครและการพากย์ทั้งเรื่องด้วย Dola Seed Audio

## ขอบเขต

Dub & Sub Studio มีหน้าตั้งค่าเสียงพากย์แยกจาก Editor ผู้ใช้สร้างและบันทึก preset ด้วย Dola Seed Audio จับคู่เสียงกับผู้พูด และสร้างเทครายประโยคได้ หน้าต่างจับคู่เปิดได้หลังใช้ผลถอดที่มีผู้พูด หรือเปิดจาก Editor เอง งานระยะต่อไปครอบคลุมการประเมินคุณภาพเสียงข้ามภาษา การตรวจทานบทสำหรับสร้างเสียงเป็นชุด และการพากย์ทั้งเรื่องตามข้อ 4

## 1. หน้าตั้งค่าเสียงพากย์

ค่าเริ่มต้นมี 10 แนว แต่ละแถวแก้ชื่อ บันทึก หรือยกเลิกได้ในรายการเดิม การเปลี่ยนชื่อใช้ revision ของ preset และคงไฟล์เสียงกับการจับคู่ตัวละครไว้

ขณะแก้ชื่อ ช่องพิมพ์แทนชื่อในแถวเดิม พร้อมปุ่มบันทึกและยกเลิกที่อยู่คู่กัน รายละเอียดเสียงยังอ่านได้ กดฟังในรายการเพื่อเล่นทันที ปุ่มเดิมเปลี่ยนเป็นหยุดโดยไม่เปิดแผงเครื่องเล่น เมื่อจบหรือหยุด ปุ่มกลับเป็นฟังตัวอย่าง เริ่มฟังแถวใหม่แล้วเสียงเดิมหยุด

ฟอร์มส่งรหัสแนวหนังแยกจากคำอธิบายทั้งโหมดคำอธิบายและคลิปต้นแบบ เปลี่ยนหรือยกเลิกแนวได้โดยรักษาข้อความเดิม รายการเสียงแสดงแนวหนังที่บันทึก กรองเพศได้ และอ่านเสียงรุ่นเดิมที่มีวลีแนวหนังท้ายคำอธิบายได้

ใน Dub & Sub Studio ให้มีหน้า **ตั้งค่า → เสียงพากย์ / Setup → Dubbing voices** เปิดได้แม้ยังไม่ได้สร้างโปรเจกต์ เมื่อกด **สร้างเสียงพากย์** ให้เลือกวิธีสร้างสองแบบ

| วิธีสร้าง | ข้อมูลที่ผู้ใช้ใส่ | การสร้างตัวอย่าง |
|---|---|---|
| **จากเสียงต้นแบบ** | อัปโหลดคลิปเสียงที่มีสิทธิ์ใช้ ฟังต้นฉบับ เลือกภาษาที่จะให้พูด และกรอกประโยคทดลองแยกจากคำกำกับ | ส่งไฟล์อ้างอิงผ่านบริการฝั่งเซิร์ฟเวอร์ พร้อมบททดลองที่อ้างถึง `@Audio1` ให้ฟังต้นฉบับและผลสังเคราะห์สลับกันได้ ตรวจรูปแบบ ขนาด และระยะเวลาตามข้อจำกัดของ provider ก่อนสร้าง |
| **จากคำอธิบาย** | บรรยายเนื้อเสียง สำเนียง จังหวะและบุคลิก เช่น “เสียงหญิงไทยวัยผู้ใหญ่ ทุ้มอุ่น พูดช้าและชัด” และกรอกประโยคทดลอง | ส่งคำบรรยายและบททดลองใน `text_prompt` แบบ text-only ผู้ใช้ฟัง ปรับคำบรรยาย และสั่งสร้างตัวอย่างใหม่ได้ |

ทั้งสองแบบตั้งชื่อและเลือกภาษาพากย์ได้ แสดงราคาก่อนสั่งสร้างตัวอย่าง การฟังคลิปที่สร้างแล้วใช้ไฟล์เดิม เมื่อกด **บันทึกเสียงพากย์** จึงเพิ่ม preset ส่วนตัว พร้อมป้ายบอกวิธีสร้างและตัวอย่างที่ผู้ใช้เลือก ให้เลือกจาก modal จับคู่ผู้พูดได้ในหลายโปรเจกต์ การยกเลิกร่างจะไม่เพิ่มเสียงลงรายการ สีประจำผู้พูดและการจับคู่เก็บแยกตามโปรเจกต์ เสียง catalog ที่ผูกกับงานเก่ายังอ่านได้ตามเดิม

**การใช้เสียงซ้ำ** ให้แต่ละ preset มี ID และเวอร์ชันของระบบ เก็บตัวอย่างที่ยืนยันเป็นไฟล์ส่วนตัวถาวรตามอายุของ preset สำหรับเสียงจากคำอธิบาย ให้ใช้ตัวอย่างที่เลือกเป็น reference สำหรับบทถัดไป และแยกอารมณ์รายฉากจากบุคลิกพื้นฐาน ต้องทดสอบความต่อเนื่องของเสียงด้วยบทคนละประโยคก่อนเปิดใช้งานจริง โดยเฉพาะกรณีต้นฉบับภาษาจีนและพากย์ภาษาไทย สำหรับเสียงจากไฟล์ต้นแบบ ระบบเก็บเสียงต้นแบบฉบับ WAV ส่วนตัวไว้จนเจ้าของลบ preset และใช้ต้นแบบนี้อ้างอิงสำหรับประโยคถัดไป

**ขอบเขต API** ตัวเชื่อมต่อรองรับ Speaker ID จาก catalog การสร้างจากคำบรรยาย และการส่งไฟล์เสียงอ้างอิงส่วนตัวผ่าน Generation เดิม ผลของ API สร้างเสียงเป็นไฟล์เสียง จึงผูก preset กับไฟล์ที่ระบบเก็บเอง แยกจาก Speaker ID ของเสียงสำเร็จรูป [BytePlus Audio 1.0](https://docs.byteplus.com/en/docs/byteplusvoice/seedaudio-01?lang=en)

## 2. แยกว่าใครพูดตอนไหน

เริ่มจาก speaker label ในผลถอด Gemini ที่มีอยู่ หากยังแยกตัวละครไม่ได้ ให้ประเมินการทำ speaker diarization จากแทร็กเสียงต้นฉบับใน post-processing แล้วจับคู่ช่วงพูดกับ cue ตามระยะเวลาที่ซ้อนกัน ใช้รหัสผู้พูดคงที่ภายในโปรเจกต์ รองรับผู้พูดสามคนขึ้นไปและหลายคนที่ลักษณะเสียงคล้ายกัน ให้ผู้ใช้กดฟังต้นฉบับ ตั้งชื่อ รวม/แยกกลุ่ม และแก้เฉพาะประโยคได้ กรณีสองคนพูดทับกันหรือ cue มีผู้พูดสลับกัน ให้แสดง “ตรวจผู้พูด” และเปิดให้แบ่งช่วง

ใช้บริบทในบทสนทนา ชื่อตัวละคร และการฟังตัวอย่างช่วยเลือกเสียงหญิงหรือชายจาก catalog หลักฐานที่ไม่พอให้คงสถานะ “ยังไม่เลือกเสียง” เก็บการจับคู่ที่ผู้ใช้ยืนยันเมื่อถอดใหม่ และชี้ช่วงที่เวลาเปลี่ยนให้ตรวจ การจำแนกกลุ่มเสียงไม่ได้ให้เพศหรือชื่อจริงของบุคคล

กติกาเสนอเสียงอัตโนมัติเรียงตามหลักฐาน ใช้คู่ผู้พูด–ตัวละครที่ผู้ใช้ยืนยันในโปรเจกต์ก่อน ถัดมาใช้ชื่อผู้พูดจากบทกำกับที่ตรงกับตัวละครที่มี preset จากนั้นจึงเสนอเสียงที่เข้ากับภาษาและลักษณะเสียงพากย์ที่ระบุในข้อมูลตัวละคร ให้ฟังตัวอย่างจริงเทียบกันก่อนยืนยัน คำเรียก “คุณชาย” อาจหมายถึงคนฟัง จึงใช้คำนี้คำเดียวตัดสินคนพูดไม่ได้ ผู้พูดคนละคนต้องมีรหัสแยกกันแม้เลือกเสียงพากย์ประเภทเดียวกัน

### 2.1 Modal “ตรวจผู้พูดและเลือกเสียงพากย์”

1. เมื่อแยกเสียงเสร็จและพบผู้พูด ให้เปิด modal ใน Editor หนึ่งครั้งสำหรับผลรอบนั้น แสดงจำนวนผู้พูดและภาษาที่กำลังจับคู่ หากไม่พบเสียงพูดให้แจ้งผลใน Editor ผู้ใช้เปิด modal ซ้ำจากคำสั่ง **จัดการผู้พูด** ได้โดยใช้ผลเดิม
2. แสดงหนึ่งแถวต่อผู้พูด เรียงตามเวลาที่พูดครั้งแรก แต่ละแถวมี **สีและชื่อผู้พูด · เพศที่ใช้กำกับบท · ลักษณะการพูด · ฟังต้นฉบับ · เลือกเสียงพากย์** ชื่อเริ่มต้นใช้ “ผู้พูด 1”, “ผู้พูด 2” ตามลำดับ ปุ่มฟังเล่นช่วงสั้นที่มีเสียงของคนนั้นพร้อมแสดงเวลา ให้ผู้ใช้แก้ชื่อ สี เพศ และลักษณะการพูดได้ ค่าที่ระบบเสนอแสดงว่า “แนะนำ” หากไม่มีหลักฐานเพียงพอให้แสดง “ยังไม่ระบุ” บนจอแคบจัดหนึ่งผู้พูดเป็นหนึ่งการ์ดตามลำดับเดิม
3. ช่อง **เลือกเสียงพากย์** แสดงเฉพาะ preset ที่บันทึกใน Setup และรองรับภาษาเป้าหมาย ให้ฟังเสียงพากย์เทียบกับต้นฉบับได้ หากยังไม่มีเสียงที่ต้องการ ให้กด **ไปตั้งค่าเสียงพากย์** เมื่อบันทึกหรือย้อนกลับ ให้คืนสู่ modal ที่ผู้พูดและภาษาเดิม เก็บตัวเลือกที่ทำไว้กับผู้พูดคนอื่น และแสดง preset ที่เพิ่งบันทึกให้เลือกได้ทันที
4. กด **บันทึกการจับคู่** เพื่อใช้กับทุกช่วงของผู้พูดคนนั้นในภาษาที่เลือก รวมถึงป้ายบน Timeline โดยรักษาเสียงที่ผู้ใช้กำหนดเฉพาะประโยคไว้ บันทึกบางคนก่อนได้ คนที่เหลือแสดง “ยังไม่เลือกเสียง” และรวมอยู่ในรายการที่ต้องแก้ก่อนพากย์ทั้งเรื่อง การปิดโดยยกเลิกให้ใช้ค่าที่บันทึกไว้ครั้งล่าสุด การยืนยันการจับคู่และการตรวจรับคำแปลเป็นคนละขั้น การสร้างเทคเริ่มเมื่อผู้ใช้สั่งพากย์

**เกณฑ์ตรวจรับ** ใช้โปรเจกต์ที่มีผู้พูดสามคน โดยสองคนเป็นผู้หญิงแต่พูดต่างจังหวะ ต้องเห็นสามแถวที่แยกด้วยทั้งชื่อและสี ฟังแต่ละคนได้ ไป Setup เพื่อเพิ่มเสียงให้คนที่สามแล้วกลับมาโดยตัวเลือกสองคนแรกยังอยู่ เมื่อบันทึก ให้เปิดโปรเจกต์อีกครั้งแล้วเห็นชื่อ สี และเสียงตรงกับป้ายของทุกช่วงในภาษาที่เลือก

## 3. ตรวจคำแปลและกำกับบน Timeline

แต่ละ cue และภาษาเก็บคำแปล ข้อความที่จะพูด ผู้พูด เสียง อารมณ์ และสถานะตรวจทาน ผู้ใช้ตรวจเองแล้วกด “ตรวจแล้ว” ทีละประโยคหรือยืนยันหลายประโยคที่เลือก การแปลอัตโนมัติอย่างเดียวไม่ถือว่าตรวจแล้ว บันทึก revision ของข้อความที่ตรวจ ถ้าแก้ข้อความหรือแปลใหม่ให้เฉพาะช่วงและภาษานั้นกลับมารอตรวจ หากเปลี่ยนเสียงหรือคำกำกับให้เทคเดิมแสดงว่าเป็นรุ่นก่อนหน้า

บนแทร็กภาษาแปลใต้ waveform วางป้ายสีที่มุมขวาบนของคลิปแต่ละช่วง ใช้สีประจำตัวละครและชื่อสั้นบนป้าย ให้เห็นเวลาเริ่ม–สิ้นสุด ระยะเวลาของช่วง และเสียงพากย์ได้จากคลิป เมื่อพื้นที่แคบย่อเป็นชื่อย่อ กด แตะ หรือโฟกัสเพื่ออ่านข้อมูลเต็มและฟังต้นฉบับ หลังสร้างเสียงให้แสดงระยะเวลาเทคจริงเทียบกับระยะเวลาช่อง ใช้ข้อความหรือสัญลักษณ์บอกสถานะร่วมกับสี ป้ายต้องไม่บังขอบลากหรือแย่งคำสั่ง seek บนคลิป

### 3.1 อารมณ์เริ่มต้นของบทพากย์

เมื่อผู้ใช้สั่งถอดฉาก ให้ Gemini ฟังน้ำเสียงประกอบบริบทและเรื่องย่อ แล้วคืนอารมณ์ ความเข้ม จังหวะ และคำกำกับสั้น ๆ ในผลเดิมรายประโยค เมื่อแปลจากข้อความอย่างเดียวให้ประเมินจากบทเท่าที่มี เก็บผลตามภาษาพากย์ แถวบทเปิดแผงแก้ไขได้จากป้ายอารมณ์ การประเมินราคาเทคและการสร้างเสียงใช้ค่าที่เห็นในแผง โดยแยกคำกำกับออกจากข้อความที่พูด

ลำดับส่งมอบคือเพิ่มผลลัพธ์แบบมีโครงสร้างใน Gemini เก็บค่าแนะนำแยกจากช่องที่ผู้ใช้แก้ แล้วเชื่อมเข้าแผงพากย์เดิม ตรวจรับด้วยการถอด แปลใหม่ แก้อารมณ์ บันทึก เปิดซ้ำ และตรวจคำขอเทค โปรเจกต์เดิมเปิดได้ด้วยค่าที่เคยบันทึก การแก้เฉพาะช่องมีผลกับประโยคและภาษานั้น เมื่อถอดใหม่ให้คงค่าที่แก้สำหรับประโยคเดิมที่จับคู่ได้

ผลตรวจด้วยข้อมูลจำลองใน `test/dubSceneTranscription.test.mjs` ครอบคลุมการถอด แปลซ้ำ เก็บคำกำกับที่แก้เอง และเปิดผลเดิมโดยไม่ส่งคำขอซ้ำ ส่วน `DubVoice.test.tsx` และ `web-next/test/dub-voice-roundtrip.mjs` ตรวจคำกำกับที่ส่งตอนเตรียมเทคและการแก้ผ่านป้ายในหน้า Editor ที่ความกว้าง 390, 820 และ 1440 พิกเซล การประเมินความเหมาะสมของอารมณ์ยังต้องฟังกับคลิปละครจริง

## 4. ปุ่ม “พากย์ทั้งเรื่อง”

ผู้ใช้เลือกภาษา ตรวจผู้พูด ฟังต้นฉบับหรือเสียงที่บันทึกไว้ แล้วจับคู่เสียงก่อนพากย์ ปุ่มฟังแสดงสถานะเฉพาะผู้พูดที่กำลังเล่น แม้หลายคนใช้เสียงเดียวกัน เปิดหน้าตั้งค่าเสียงได้จากจุดเดียว สำหรับแต่ละคำสั่งสร้าง ให้ตรวจทุกช่วงในขอบเขตนั้นว่ามีบทและเสียงพร้อม พร้อมแสดงเวลาของช่วงที่ต้องแก้ การเปลี่ยนข้อมูลหลังเตรียมราคาต้องเตรียมใหม่ก่อนยืนยัน ผู้ใช้พักคิวระหว่างช่วงและกลับมาทำต่อได้ บนจอแคบให้พิมพ์คำแปลในแถวได้โดยตรงและเปิดแผงกำกับเสียงเมื่อกดปุ่มของแถวนั้น

ทางเข้าหลักอยู่เหนือบทสนทนา เปิด modal โดยเริ่มที่ภาษาของ Editor และสลับภาษาพากย์ได้ หนึ่งแถวต่อผู้พูดแสดงสี ชื่อ ประเภทเสียง จำนวนประโยค และปุ่มฟังเสียงจริงกับเสียงจาก Setup การตรวจผู้พูดเพิ่มเติมอ่านเสียงต้นฉบับและเติมเฉพาะผู้พูดในคิวเดิมที่จับคู่ตามเวลาได้ เก็บคำแปล เวลา และเทคที่ตรวจไว้ ช่วงที่ไม่ชัดให้ผู้ใช้ระบุเอง

ปุ่มหลักสร้างเฉพาะประโยคที่ยังไม่มีเทคของภาษานั้น เช่น มีเทคแล้ว 3 จาก 24 ให้เสนอ 21 ประโยค การแทนที่ทั้งเรื่องเป็นคำสั่งรองแยกต่างหาก ระบุจำนวนก่อนเริ่ม แสดงความก้าวหน้ารายประโยคและคงงานสำเร็จไว้เมื่อบางประโยคล้มเหลว คลิกบทแปลเพื่อกำกับเทครายประโยคโดยใช้เสียงที่บันทึกจากหน้า Setup เช่นเดียวกัน

1. เลือกภาษาเป้าหมาย ระบบนับช่วงที่มีบทพูดทั้งหมด แยกช่วงที่ตรวจแล้วและผูกเสียงแล้ว ช่วงที่ขาดบทหรือเสียงกดเพื่อไปแก้ได้ ช่วงเงียบหรือช่วงที่ผู้ใช้เลือกข้ามให้ระบุชัด
2. เมื่อพร้อม แสดงจำนวนช่วงที่จะสร้างและประมาณการรวมจากใบเสนอราคารายประโยค ผู้ใช้ยืนยันหนึ่งครั้ง ระบบยึดข้อความที่ตรวจแล้วและเวอร์ชันเสียง ณ เวลายืนยัน ใช้บทพากย์ที่แก้ไว้ก่อนคำแปล ใส่คำกำกับแยกจากคำที่ต้องการให้พูด
3. ส่งรายการผ่านบริการสร้างเทคและระบบ Credits เดิม จำกัดจำนวนงานพร้อมกัน รายงานความคืบหน้าจริงรายช่วง การเปิดหน้าใหม่หรือลองซ้ำใช้ operation เดิม กรณีผล provider ยังไม่ทราบต้องตรวจสถานะก่อนส่งอีกครั้ง รักษาเทคที่สำเร็จและลองใหม่เฉพาะช่วงที่จำเป็น
4. วางเทคตามเวลาเริ่มของแต่ละ cue ในแทร็กพากย์ของภาษาที่เลือก ให้ฟังทั้งเรื่องเทียบกับภาพได้ทันที ช่วงที่ยาวเกินหรือชนบทถัดไปแสดงจุดให้ผู้ใช้ย่อบทหรือสร้างเทคใหม่ เก็บเทคเดิมไว้จนกว่าจะรับชุดใหม่ ส่งออก WAV หรือวิดีโอผ่าน renderer เดิม เมื่อเสียงต้นฉบับมีดนตรีรวมกับบทพูด ให้มีทางเลือกลด/ปิดแทร็กต้นฉบับ การเก็บดนตรีและลบเฉพาะเสียงพูดต้องมี stems หรือแยกแหล่งเสียงเพิ่ม

### เวลาบทพากย์และการตรวจคำย่อ

เวลาที่อนุญาตให้พูดในแต่ละเทคเท่ากับเวลาจบลบเวลาเริ่มของ cue งานรายช่วงและงานทั้งเรื่องต้องส่งช่วงเวลาแบบสัมพันธ์กับจุดเริ่มเทคเข้า Seed เสมอ ก่อนพากย์ทั้งเรื่องให้ประเมินบทพูดกับเวลา ส่งเฉพาะบทที่คาดว่าจะล้นหรือเคยล้นให้ Luna ย่อโดยอ้างอิงต้นฉบับ บทข้างเคียง บริบทเรื่องและอารมณ์ ผู้ใช้เห็นบทเดิม บทที่เสนอ และเวลาที่มี แก้หรือเก็บบทเดิมได้ก่อนสร้าง บันทึกคำย่อเฉพาะบทพากย์ของภาษานั้น

หลังสร้างให้ตรวจความยาวไฟล์จริง ตัดปลายที่เงียบได้โดยคงคำพูด หากยังล้นให้แสดงระยะเวลาจริงเทียบกับช่วงบท คงเทคเดิมและให้แก้เฉพาะช่วงที่ล้นได้

**จังหวะจากเสียงต้นฉบับ** ทั้งการพากย์รายประโยคและทั้งเรื่องต้องตรวจช่วงเสียงพูดภายใน cue และใช้เวลาเทียบจากต้น cue เดียวกัน ตัวอย่าง cue ยาว 3 วินาที ถ้าต้นฉบับพูดช่วง 0.4–1.2 และ 1.8–2.8 วินาที ให้ Luna เห็นทั้งสองช่วง รวมเวลาที่พูดได้จริง และบริบทข้อความก่อนเสนอคำย่อ ให้ Dola ได้รับบทที่ตรวจแล้วพร้อมจังหวะเริ่ม พัก และจบ หากตรวจจับไม่ได้ให้ใช้กรอบเวลา cue เดิม

ตรวจเสียงที่สร้างจริงและชดเชยเฉพาะส่วนเงียบนำที่จำเป็นก่อนวางไฟล์ที่ต้น cue ทั้งการฟังและส่งออกใช้เทคเดียวกัน เมื่อจังหวะเริ่ม จบ หรือพักคลาดเกินเกณฑ์ ให้ระบุช่วงบทที่ควรฟังทวนและรักษาเทคเดิมในการพากย์อัตโนมัติ งานนี้วัดจังหวะจากเสียงและไม่วิเคราะห์การขยับปากในเฟรมวิดีโอ

### งานปรับหน้าต่างจับคู่เสียงพากย์

- **ส่วนหัว** วางชื่อ “พากย์ทั้งเรื่อง” กับจำนวนผู้พูดไว้ด้วยกัน จัดตัวเลือกภาษาและปุ่ม “ตั้งค่าเสียงพากย์” เป็นกลุ่มเดียวกันอีกด้าน
- **รายชื่อผู้พูด** ให้แต่ละคนมีแถวที่แยกจากกันชัดเจน ชื่อผู้พูดเป็นข้อความหลัก ตามด้วยจุดสี ประเภทเสียง และจำนวนประโยค จัดช่องเลือกเสียงให้ตรงกันทุกแถว วางปุ่ม “ฟังเสียงต้นฉบับ” และ “ฟังเสียงพากย์” ใกล้ช่องเลือกเสียงของคนนั้น เก็บ “แก้ข้อมูลผู้พูด” เป็นคำสั่งรองที่กางได้
- **ส่วนท้าย** รวมช่องยืนยันว่าตรวจบทแล้วกับปุ่มหลัก “พากย์ N ประโยคที่เหลือ” ไว้ด้วยกัน ให้ “บันทึกการจับคู่” และ “ปิด” เป็นปุ่มรอง ผู้ใช้ต้องแยกได้ทันทีว่าปุ่มใดเพียงบันทึกและปุ่มใดเริ่มสร้างเสียง
- **เกณฑ์ตรวจรับ** ใช้ตัวอย่างคุณชายและนางเอก คนละ 3 ประโยค บนจอกว้างต้องไล่ดูชื่อ เสียงที่เลือก และปุ่มฟังของทั้งสองคนในแนวเดียวกันได้ บนมือถือให้เรียงข้อมูลแต่ละคนในคอลัมน์เดียว ชื่อเสียงยาวหรือการกางรายละเอียดต้องไม่ดันปุ่มออกนอกหน้าต่าง เมื่อมีผู้พูดหลายคนต้องเลื่อนดูรายการและเข้าถึงปุ่มท้ายหน้าต่างได้

## 4.1 รูปแบบ prompt สำหรับพากย์บทสนทนาทั้งฉาก

ข้อกำหนดสำหรับการพัฒนารอบถัดไป ผู้ใช้เขียนแนวทางของฉากหรือเลือกช่วงบทที่ตรวจแล้ว ระบบนำบริบทเรื่อง โปรไฟล์เสียงของผู้พูด และอารมณ์รายประโยคมาจัดเป็น prompt สำหรับ `seed-audio-1.0-multilingual` เปิดดูและแก้คำกำกับฉบับที่จะส่งได้ก่อนสร้างเสียง ตัวอย่างสองฉากด้านล่างใช้ผู้ใหญ่สองคน จำนวนผู้พูด ชื่อ ภาษา และระยะเวลาให้มาจากฉากจริง

```text
Create a cinematic {genre} dialogue between {speaker_count} characters.
LANGUAGE: {spoken_language}
TOTAL DURATION: {duration_seconds} seconds
AUDIO: Dialogue only. No narrator, music, ambience, or sound effects.

CHARACTER {n} — {speaker_name} ({role})
{age_if_known}, {timbre}, {pitch}, {resonance}, {articulation}, {baseline_personality}

VOICE CONSISTENCY
Keep each speaker's voice distinct and consistent throughout the scene.

ACTING DIRECTION
{What each character wants, how they listen and react, and how the mood changes.}

TIMESTAMPED DIALOGUE
[{start}s:{end}s] {speaker_name} ({direction_for_this_line})
"{verbatim_approved_dialogue}"
[{last_line_end}s:{scene_end}s] Natural silence.

PERFORMANCE RULES
Use natural conversational pacing and pronunciation. Respect the assigned times.
Keep the spoken words exactly as written. No overlapping dialogue.
```

**การประกอบข้อความ** ให้โมเดลข้อความช่วยเรียบเรียงเฉพาะบุคลิกเสียงและคำกำกับการแสดง เช่น ตอบด้วยความแปลกใจก่อนกลบเกลื่อนความเขิน ระบบเติมชื่อผู้พูด บทที่ตรวจแล้ว และเวลาเริ่ม–จบจาก timeline เอง โดยแปลงเป็นวินาทีสัมพัทธ์จากต้นฉาก เพิ่มช่วงเงียบท้ายเมื่อมีเวลาว่างจริง หากข้อความเกินขนาดที่ Seed รับ ให้ย่อคำกำกับก่อนและแจ้งหากต้องแบ่งฉากที่รอยต่อประโยค รักษาบทพูดทุกคำ

**ตัวปรับ prompt** ใช้ configuration ฝั่ง server เลือกโมเดลข้อความที่มีต้นทุนโดยประมาณต่ำกว่าสำหรับจำนวนโทเคนเข้าและออกของงาน ณ 21 พ.ย. 2026 ค่าเริ่มต้นสำหรับ API แบบ Standard ที่ชำระเงินคือ `gpt-6-luna` ($0.10 เข้า / $0.50 ออก ต่อหนึ่งล้านโทเคน) เทียบกับ `gemini-3.5-flash-lite` ($0.30 / $2.50) คิดค่าเรียบเรียงแยกจากค่าสังเคราะห์เสียงของ Seed การกลับมาเปิด prompt เดิมใช้ฉบับที่เตรียมไว้ [OpenAI Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) · [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing.md)

**ฉากอ้างอิงสำหรับตรวจรับ** เทียบตำแหน่งด้วยนาฬิกาของฉาก และเทียบผู้พูดกับบทต้นฉบับทีละประโยค

### ตัวอย่างเสียงคนเดียวในหน้า Setup

Luna เตรียมคำกำกับภาษาอังกฤษ หากบริการ Luna ขัดข้อง ให้ Gemini รับข้อมูลฟอร์มและบทพูดเพื่อกำกับทั้งฉาก อารมณ์ และระยะเวลา ทั้งคำบรรยายไทยและอังกฤษ หากยังมีคำกำกับไทยให้แปลก่อนส่ง Seed โดยรักษาบทพูดเดิม หากทั้งสองบริการขัดข้องให้ลองใหม่ ระหว่างสร้างตัวอย่างแสดงคลื่นเคลื่อนไหวพร้อมสถานะ และแสดงคลื่นนิ่งเมื่อผู้ใช้เลือกลดการเคลื่อนไหว

หลังเรียบเรียงคำกำกับแล้ว เซิร์ฟเวอร์เลือกวลีจาก `server/config/voice-studio/dubbing-genres.json` ตามรหัสแนวหนังและภาษาพูด ใส่ใน CHARACTER และย้ำท้าย PERFORMANCE RULES ก่อนส่ง Seed Audio หากไม่ได้เลือกแนวให้ใช้ Professional Thai dubbing. สำหรับภาษาไทย หรือใช้ชื่อภาษาพูดที่เลือก ใบงานเดิมที่มีวลีสไตล์ท้ายคำอธิบายยังใช้ได้

หากบริการเรียบเรียงคำกำกับส่งข้อผิดพลาด ให้สร้างคำกำกับตาม schema จากข้อมูลในฟอร์ม เก็บบทและเสียงต้นแบบเดิม ส่ง Seed ครั้งเดียวในงานนั้น และแสดงที่มาของคำกำกับพร้อมตัวอย่าง

ใช้ฟอร์มเดิมทั้งแบบคำบรรยายและคลิปต้นแบบ หลังรับงาน ให้ Luna รับเฉพาะข้อมูลข้อความและเติมสี่ช่องบังคับ ได้แก่ ลักษณะเสียงถาวร ฉาก คำกำกับการแสดง และเวลาเป้าหมายของตัวอย่าง เซิร์ฟเวอร์ตรวจผล นำชื่อ ภาษา เพศ และบทเดิมมาประกอบ monologue พร้อมช่วงพูดและช่วงเงียบตามความยาวตัวอย่าง คลิปต้นแบบส่งตรงให้ Seed ด้วย @Audio1 หน้าผลลัพธ์เปิดดู prompt ที่ส่งจริงได้ คำกำกับฉากอยู่ในเทคตัวอย่าง ส่วนการพากย์ครั้งถัดไปใช้เสียงที่ผู้ใช้บันทึกกับอารมณ์ของบทใหม่

### ร่างคำอธิบายเสียงจากบทบาท

ในรายการเทครายประโยค การฟังเทคให้เริ่มตามตำแหน่งเสียงบนไทม์ไลน์และหยุดภาพพร้อมเสียงที่จุดจบคำพูดที่วัดได้ หรือปลายไฟล์เมื่อไม่มีข้อมูลจังหวะ ใช้คำสั่งลบแยกรายเทคหลังยืนยัน โดยคงเทคที่มีการใช้งานตามการตรวจของ Voice Studio

การสุ่มหนึ่งครั้งเติมคำอธิบายเสียงพร้อมบทตัวอย่างตามภาษาพูด ถ้าผู้ใช้เขียนบทตัวอย่างเองให้เก็บไว้ ช่องคำอธิบายเก็บข้อความที่ผู้ใช้แก้ไข ส่วนวลีแนวหนังแสดงใน prompt ที่ส่งจริง ฟอร์มอยู่บนหน้าจอระหว่างสร้างเสียง โดยมีแผงโปร่งแสงป้องกันการกดซ้ำ เมื่อเสร็จให้ฟังตัวอย่างด้านล่าง แก้ฟอร์มและสร้างเสียงใหม่ได้ในหน้าเดิม กดบันทึกจึงเพิ่มเสียงลงรายการ

ในหน้า Setup ให้วางแนวหนังเหนือกรอบ AI ภายในกรอบมีช่องบทบาทตัวละคร (ไม่บังคับ) และปุ่มสุ่มคำอธิบายเสียง เว้นบทบาทว่างแล้วกดสุ่มได้ทันที แสดงผลในช่องคำอธิบายเสียงที่แก้ไขได้ใต้กรอบ ใช้ชื่อ ภาษา ประเภทเสียง แนวหนัง และบทบาทที่กรอกเป็นข้อมูลตั้งต้น ให้ร่างได้แม้ยังไม่มีบทตัวอย่าง ผู้ใช้เลือกสร้างเสียงในขั้นถัดไป เมื่อร่างไม่สำเร็จให้เก็บข้อความเดิมไว้ แนวหนังเลือกได้ 15 แบบจาก configuration JSON

จัดการ์ดสร้างเสียงให้อยู่กลางพื้นที่ทำงาน อ่านช่องกรอกจากซ้ายไปขวาตามปกติ ขณะรอสร้างให้จัดหัวข้อ คลื่นเสียง ข้อความสถานะ และปุ่มตรวจสถานะไว้กึ่งกลาง ใช้คลื่นเสียงเดียวกันสำหรับสร้างตัวอย่าง พากย์ประโยค และพากย์ทั้งเรื่อง รองรับการลดการเคลื่อนไหว

### เมื่อ Seed ตอบกลับแต่บันทึกตัวอย่าง WAV ไม่สำเร็จ

Assets ตรวจและแปลง WAV ที่ถอดรหัสได้เป็น PCM mono 24 kHz สำหรับฟังและใช้พากย์ต่อ หากไฟล์ตัวอย่างใช้ไม่ได้ก่อนบันทึก Generation คืนเครดิตที่กันไว้ผ่าน Credits และจบงานพร้อมเก็บรหัสข้อผิดพลาด ปุ่มตรวจสถานะต้องกู้กรณีเดียวกันของงานเดิมได้โดยไม่สังเคราะห์ซ้ำ หน้า Setup อธิบายสาเหตุและให้กลับไปตั้งค่าเสียงเพื่อขอราคาใหม่ ถ้าผลส่งคำขอยังไม่แน่นอน ให้คงกระบวนการตรวจสอบงานเดิม

### จัดเวลาจากเทคเดิม

ทุกครั้งที่กดจัดเวลา ให้แจ้งผลเมื่อเสร็จ แม้ตำแหน่งจะเหมือนเดิม ให้ระบุจำนวนที่วางเพิ่มกับจำนวนที่ต้องฟังทวน เพื่อให้แยกผลที่ไม่มีเทคผ่านเพิ่มออกจากปุ่มที่ไม่ตอบสนอง

#### ทางออกเมื่อบทพากย์ติดการตรวจจังหวะ

ในชุดที่สำเร็จบางส่วน ผู้ใช้เปิดตรวจเฉพาะบทที่ยังค้าง ดูข้อความที่ใช้พากย์จริง และเลือกขอให้ AI ปรับบทตามช่วงเสียงหรือยืนยันข้อความในช่องได้ทันที ข้อเสนอจาก AI ต้องแสดงให้ตรวจและแก้ก่อนสร้างเสียง การยืนยันสร้างและใช้เสียงตามบทนี้ยอมรับจังหวะพูดที่คลาดได้ภายในพื้นที่วางเสียง โดยยังตรวจความยาว ขอบฉาก แทร็กที่ล็อก และการทับเสียงข้างเคียง การกลับมาเปิดงานเดิมต้องใช้การตัดสินใจที่บันทึกไว้กับชุดนั้น

ตรวจผ่านทางเข้าหน้า Speaker Review ด้วย API จำลอง ตรวจค่าที่ส่งให้ batch และตรวจการวางเสียงด้วยชุดทดสอบของ DubBatchService โดยไม่ยิงงานพากย์จริง

#### วิเคราะห์เสียงและสร้างเสียงพากย์

แบ่งแผงตามสิ่งที่ผู้ใช้ต้องการทำ โดยจัดลำดับดังนี้

1. **ตรวจจังหวะเสียงพากย์** ใช้ปุ่ม **วิเคราะห์เสียงในซีน** ใต้ปุ่มอธิบายว่า “เทียบเสียงพากย์ที่มีอยู่กับจังหวะพูดต้นฉบับ แล้วเลื่อนเสียงให้ตรงกับภาพเมื่อทำได้ ประโยคที่คุณเลือกเสียงไว้แล้วจะอยู่ที่เดิม” กดได้โดยไม่ต้องยืนยันบทหรือสร้างเสียงใหม่
2. **ผลการวิเคราะห์** แสดงสรุปเพียงครั้งเดียว เช่น “ใช้เสียงพากย์ในฉากแล้ว 4 จาก 6 ประโยค” แล้วจัดรายการที่เหลือใต้ข้อความที่บอกสาเหตุจริง เช่น “อีก 2 ประโยคมีเสียงพากย์แล้ว แต่ช่วงพักยังไม่ตรงกับต้นฉบับ” ให้เลือกเวลาเพื่อไปฟังประโยคนั้นพร้อมภาพได้ทันที แถวแสดงเวลาและบท ถ้าทั้งกลุ่มมีสาเหตุเดียวกันไม่ต้องพิมพ์สาเหตุซ้ำทุกแถว แยกกรณียังไม่มีไฟล์เสียงออกจากกรณีมีเสียงแล้วแต่จังหวะคลาด เมื่อวิเคราะห์ซ้ำแล้วผลเท่าเดิม ให้อัปเดตสรุปเดิมด้วยคำสั้น ๆ ว่า “วิเคราะห์แล้ว ผลเหมือนเดิม”
3. **สร้างเสียงพากย์** วางช่องยืนยันบทไว้ในส่วนนี้ สำหรับตัวอย่างที่มีเสียงแล้วแต่จังหวะคลาด ใช้ปุ่ม **พากย์ใหม่เฉพาะ 2 ประโยคนี้** โดยจำนวนและรายการต้องตรงกับคำขอจริง ใต้ปุ่มระบุว่า “สร้างเสียงพากย์รอบใหม่ให้ประโยคในรายการด้านบน อีก 4 ประโยคใช้เสียงเดิม” ถ้าเป็นประโยคที่ยังไม่มีเสียง ให้ใช้ **พากย์ [จำนวน] ประโยคที่ยังไม่มีเสียง** ส่วน **พากย์ใหม่ทั้งฉาก** เป็นคำสั่งรอง แสดงจำนวนทั้งหมดและคงการยืนยันก่อนเริ่ม

เกณฑ์ตรวจ UX คือผู้ใช้บอกได้ก่อนกดว่าคำสั่งใดใช้ไฟล์เสียงเดิม คำสั่งใดสร้างเสียงใหม่ กระทบกี่ประโยค และกดตรงไหนเพื่อฟังจุดที่จังหวะคลาด ป้ายและตัวเลขต้องสะท้อนผลของโปรเจกต์จริงทั้งภาษาไทยและอังกฤษ

หลังสร้างเทคสำเร็จ ให้ตรวจจุดเริ่ม จุดจบ และช่วงพัก ณ ตำแหน่งบนไทม์ไลน์ แล้วหาค่าเลื่อนเสียงที่ผ่านเกณฑ์ทั้งหมด คงเวลาซับ ตรวจเพื่อนบ้านและขอบเขตวิดีโอ และรักษาตำแหน่งที่ผู้ใช้เลือกไว้ถ้าผ่านอยู่แล้ว หากจัดเวลาไม่ได้ให้เก็บผลเป็น “มีเสียงแล้ว · รอฟังทวน” และทำประโยคถัดไป ปุ่ม “จัดเวลาใหม่จากเทคเดิม” ต้องอ่านเฉพาะเทคของผู้ใช้ในชุดเดิม รักษาเทคที่เลือกแล้ว และไม่เรียกผู้ให้บริการหรือคิดเครดิต การสร้างเสียงใหม่เป็นคำสั่งแยก

เมื่อกด “ยืนยันบทและพากย์ต่อ” ครั้งแรก ให้บันทึกบทพากย์ที่ตรวจแล้วตามประโยคและภาษาได้ก่อนมีเอกสารเสียง จากนั้นเตรียมงานด้วยบทนั้นและเก็บซับเดิมไว้

**กล่องข้อผิดพลาดในหน้าตรวจบทพากย์ให้พอดีเวลา** เมื่อย่อบทไม่สำเร็จ ให้แสดงกล่องเดียวใต้หัวข้อและเหนือรายการประโยค ใช้กรอบ พื้นหลัง และหัวข้อ “ย่อบทไม่สำเร็จ” เพื่อให้สังเกตได้แม้แยกสีได้ยาก ภายในกล่องแสดงสาเหตุที่ทราบและปุ่มที่ใช้แก้สถานการณ์นั้น เมื่อ Luna ปฏิเสธสิทธิ์ ให้เลือก “ลอง Luna อีกครั้ง” หรือ “ส่งบทให้ Gemini ช่วยย่อ” ทั้งรายประโยคและทั้งเรื่อง เมื่อผลคำขอ Luna ยังไม่แน่นอน ให้เลือก Gemini ได้โดยไม่ส่งคำขอ Luna ซ้ำ ข้อความซับ ช่วงเวลา และช่องแก้บทยังคงอยู่ในรายการประโยคด้านล่าง

เมื่อหน้าตรวจบทให้ผู้ใช้แก้เอง ให้ API บันทึกเหตุผลพร้อมรหัสคำขอ แยกการตอบจากคำขอที่เก็บไว้กับการปฏิเสธจากผู้ให้บริการ และเก็บเฉพาะรหัสวินิจฉัยโดยไม่บันทึกบทพูดหรือคีย์

เมื่อ Luna ส่งคำแนะนำไม่ได้ ให้แสดงเหตุผลที่ทราบ ผู้ใช้เก็บหรือแก้บทเดิมได้ และเลือกส่งบทกับกรอบเวลาให้ Gemini ช่วยย่อได้เอง ใช้สิทธิ์และเพดานคำขอเดิม แยกผลตามผู้ให้บริการ คำขอเดิมที่ยังไม่ทราบผลต้องไม่ส่งซ้ำ ป้ายผู้พากย์บนคลิปซับต้องมีพื้นที่แยกจากข้อความ ถ้าคลิปสั้นให้แสดงแถบสีและดูชื่อเต็มผ่านรายละเอียดของคลิป
