# Package 003D - Seedance Portrait Reference Recovery

**Plan ID:** `016-PVP-IP-003D`  
**Status:** Implemented and verified  
**Primary capability:** Generation video provider compatibility  
**Primary role:** Generative Cinematic Production Director  
**Reviewers:** UX/UI Product Designer, QA Release Engineer  
**Triggered Skills:** `direct-generative-cinematic-production`, `implement-generation-workflow`, `review-generative-media-pipeline`, `review-product-ux`

## 1. Qualification Finding

The first live Cinematic Seedance 2.0 Mini attempt reached ModelArk with the
expected image-to-video request, one `first_frame` reference, 9:16, 720p and a
six-second duration. ModelArk rejected the request before creating a provider
task with `InputImageSensitiveContentDetected.PrivacyInformation` because the
Storyboard frame may contain a real person.

Evidence:

- local task `videotask_80b2b5ea9659e7bf3b71`;
- model `dreamina-seedance-2-0-mini-260615`;
- approved Storyboard Asset Version `ast_1788456276222_p7qcplwy`;
- source image was generated by OpenAI and is not a BytePlus-authorized
  portrait Asset;
- the one-Credit reservation was refunded and the task is terminal
  `failed/not_billable`;
- no provider task ID or output media was created.

The source is an AI-authored Character, not a claimed real person. The provider
classified the photorealistic face under its privacy-sensitive input policy.
This remains a provider trust restriction rather than a prompt, duration,
first-frame transport, Credit settlement or Storyboard lineage failure. The
development POC flag may expose unqualified models for inspection, but must not
bypass provider moderation.

## 2. Required Behavior

1. Seedance models declare that direct portrait references require a
   provider-authorized portrait Asset.
2. A Cinematic image-to-video request whose approved keyframe contains an
   authored Character must carry that fact into the canonical Generation
   request.
3. Generation rejects an unsupported Seedance portrait reference during quote,
   before Credit estimation, reservation or provider dispatch.
4. The stable application error is
   `video_provider_portrait_authorization_required`; raw provider wording is
   not used as the product contract.
5. A live provider rejection with the observed ModelArk code normalizes to the
   same stable error and remains non-retryable and not billable.
6. Produce explains that the first frame was rejected by provider portrait
   policy, confirms refund state for an attempted request, and offers an
   explicit switch to a compatible candidate. It never retries or changes
   provider automatically.
7. The current recovery candidate is `veo-3.1-lite-generate-preview`, which is
   already exposed for Cinematic draft image-to-video and retains the approved
   first frame and canonical video packet. Its own quote and user confirmation
   remain mandatory. Gemini Omni stays behind its separate operation-specific
   Cinematic qualification gate.
8. Seedance remains selectable for provider qualification and for requests
   without an authored Character. The development POC toggle and one-Credit
   policy remain unchanged.

## 3. Implementation Steps

### 003D.1 Capability and request contract

- Add `portraitReferencePolicy: provider_authorized_asset_required` to every
  Seedance catalog row that can accept a first-frame reference, including
  image modes exposed only by the development POC override.
- Add a bounded boolean `referenceContainsPerson` to the internal prepared
  request and its request fingerprint.
- Set it from Cinematic Character authority; do not infer identity from image
  pixels in the browser.
- Keep the field out of provider logs and do not include biometric data.

### 003D.2 Deterministic preflight

- Enforce the portrait-reference policy in Generation capability validation.
- Reject before estimate or reservation when a direct image reference contains
  a Character and the selected model requires a provider-authorized Asset.
- Repeat the same validation at submit through the canonical request path.
- Do not add text-to-video fallback because that would discard immutable
  first-frame and Character continuity authority.

### 003D.3 Provider error normalization

- Map ModelArk
  `InputImageSensitiveContentDetected.PrivacyInformation` to the stable
  authorization-required error.
- Preserve `retryable: false` and `providerBillableState: not_billable` so the
  existing Credit refund path remains authoritative.
- Keep provider request correlation in server diagnostics only.

### 003D.4 Produce recovery UX

- Show the terminal provider failure in the existing review section.
- Use localized Thai and English title, explanation and refund status.
- Offer `Use Veo 3.1 Lite` only when that model is present in the
  server catalog.
- Changing the model starts a fresh quote; it does not submit automatically.
- Keep attempt history, provider/model identity, Storyboard source and prompt
  visible and unchanged.

## 4. Acceptance Tests

- Seedance plus `referenceContainsPerson: true` is rejected during quote
  with the stable code and creates no estimate, reservation, ledger entry or
  provider task.
- The same Seedance model can still validate a non-person reference POC request.
- Veo 3.1 Lite accepts the same Cinematic first-frame request contract for quote.
- The observed raw ModelArk privacy code maps to the stable non-retryable,
  not-billable error.
- The failed live attempt remains refunded with zero reserved Credits.
- Produce renders the localized recovery state and switching to Veo changes
  the selected model, performs a new quote and does not auto-submit.
- Existing Generate, polling, technical probe, preview, approval and sequence
  behavior remains covered.

## 5. Deferred Provider Integration

Real-person Seedance portrait image-to-video remains out of scope until Momelo
implements and qualifies all of the following as a separate package:

- BytePlus real-person consent and authorization workflow;
- private Asset Library upload and provider Asset-group ID persistence;
- actor ownership, consent expiry, revocation and audit trail;
- adapter payload support for the authorized provider Asset ID;
- repeated paid quality, latency, billing and deletion evidence.

Synthetic Character outputs generated by a compatible Seedream model follow
Package 003E and requirement `../011-seedream-seedance-synthetic-character-keyframe-flow.md`.
No prompt wording or client-side checkbox may stand in for provider trust.
